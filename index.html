GitHub

💡
Git هو الأداة، GitHub هو المنصة. مثل Microsoft Word (الأداة) وGoogle Drive (مكان الحفظ).
📋
أوامر Git الأساسية
الأوامر التي ستستخدمينها يومياً
  • 1
    تهيئة مشروع جديد
    git init # ابدئي تتبّع المشروع
  • 2
    تحضير الملفات للحفظ
    git add . # أضيفي كل الملفات
  • 3
    حفظ نقطة تغيير (Commit)
    git commit -m "أضفت صفحة البداية"
  • 4
    رفع الكود إلى GitHub
    git push origin main # ارفعي للسحابة
  • 5
    تحميل آخر تحديثات الفريق
    git pull # حمّلي أحدث نسخة
  • 6
    عرض حالة الملفات
    git status # شوفي ماذا تغيّر
  • 7
    عرض سجل التغييرات
    git log --oneline # تاريخ كل commit

Pull Request (PR)
مراجعة الكود قبل دمجه

حين تنهين فرعك، ترسلين Pull Request لمراجعة الكود قبل إضافته للمشروع الرئيسي.

  • 1
    انهي العمل على فرعك وارفعيه لـ GitHub
  • 2
    افتحي Pull Request واشرحي ماذا فعلتِ
  • 3
    الفريق يراجع ويضع تعليقات
  • 4
    بعد الموافقة يُدمج الكود في main ✅
🌟 لماذا PR مهم؟ يضمن أن الكود مراجَع من شخص آخر مما يقلّل الأخطاء ويحسّن جودة المشروع.

GitHub Pages
انشري موقعك مجاناً!

GitHub Pages يُتيح لك نشر موقع ويب مجاناً تماماً مباشرة من مستودعك!

  • 1
    ارفعي ملفات موقعك على GitHub
  • 2
    اذهبي لـ Settings > Pages
  • 3
    اختاري الفرع main كمصدر
  • 4
    موقعك سيكون على: username.github.io/project 🎉

المرحلة 1: الفكرة والتخطيط
قبل كتابة أي كود

    حدّدي المشكلة: ما الذي يحلّه تطبيقك؟ "أريد تطبيقاً لتتبّع مصاريفي اليومية"
  • 2
    حدّدي جمهورك: من سيستخدم التطبيق؟ طلاب؟ ربّات بيوت؟ موظّفون؟
  • 3
    قائمة المميزات: ابدئي بالأساسية فقط (MVP)
  • 4

أكبر خطأ للمبتدئين: محاولة بناء تطبيق معقد جداً من البداية! ابدئي بأبسط نسخة تعمل.
📌 ما هو MVP؟
Minimum Viable Product = أبسط نسخة من التطبيق تحلّ المشكلة الأساسية. أطلقيها وخذي رأي المستخدمين، ثم طوّري بناءً على ذلك.
